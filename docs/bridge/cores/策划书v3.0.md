# LINK · 模块化架构策划书

> **项目**：LINK — Long-term Intelligent Navigation Keystone
> **标语**：帮你走得更远。
> **版本**：v3.0
> **最后更新**：2026-07-03
> **状态**：设计定稿

---

## 一、概述

### 1.1 LINK 是什么

LINK 是一套开源的 AI 长期成长系统框架。它提供模块化的核心能力——LLM 适配、AI 战友管理、记忆压缩、定时任务、知识库检索——让任何人都能搭建自己的 AI 长期陪伴系统。

### 1.2 LINK 的核心洞察

市面上的系统往往分成两类：

| 类型 | 代表 | 问题 |
|:---|:---|:----|
| **"框架"** | LangChain, AutoGen | 太技术化，普通用户配不来，配完也就是个空壳 |
| **"应用"** | ChatGPT, 各类 AI App | 功能写死，用户不能让它长成自己的形状 |

LINK 在这之间找到了一个平衡点：**给骨架，给器官，留插槽。**

```
LINK = 骨架（核心引擎） + 器官（内置工具/记忆/网关） + 插槽（Tool/Skill 扩展）
       框架写好         开箱即用                  用户按需插入
```

## 二、LINK 架构全景

### 2.1 架构总览

```
LINK Core（开源框架）

├── packages/
│   ├── @link/llm                       ← 模块: LLM 适配器
│   ├── @link/gateway                   ← 模块: 网关 + 默认 UI
│   ├── @link/memory                    ← 模块: 记忆系统
│   ├── @link/agents                    ← 模块: Agent 管理
│   ├── @link/agent-runtime             ← 模块: Agent 执行引擎
│   ├── @link/scheduler                 ← 模块: 定时任务
│   └── @link/knowledge                 ← 模块: 知识库索引
│
├── @link/admin-ui                      ← 模块 H: 管理面板（Web UI 配置）
├── create-link-app/                    ← CLI 脚手架（npm create link-app）
└── ecosystem/                          ← 社区 Skill 包注册
```

### 2.2 用户的系统长什么样

用户通过 `npm create link-app my-system` 得到：

```
my-system/
├── link.config.js          ← 所有配置在这里（也可通过管理面板配置）
├── agents/                 ← AI 战友定义（身份/性格/指令）
├── data/                   ← 记忆数据（框架自动管理）
│   ├── rooms.json
│   ├── daily-summary/
│   └── conversation-log/
├── tools/                  ← 自定义工具（YAML 配置）
├── skills/                 ← 自定义工作流（YAML 配置）
├── public/                 ← UI 主题（可选）
│   └── theme.css
└── package.json            ← 依赖 @link/*

启动后:
  http://localhost:3000      ← 聊天界面
  http://localhost:3000/admin ← 管理面板（配置界面）
```

### 2.3 核心原则

```
1. 通用核心 vs 个性化插槽

   LINK 写死的 = 通用不变的        用户配置的 = 每个人不同
   ┌──────────────────────┐     ┌──────────────────────────┐
   │ LLM 适配器            │     │ Agent 身份定义            │
   │ 记忆系统（四层压缩）   │     │ 工具注册表（ToolRegistry） │
   │ Agent 执行引擎         │     │   ├── 我的工具            │
   │ 网关路由               │     │   ├── 他的工具            │
   │ 定时任务引擎           │     │   └── 她的工具            │
   │ 知识库索引框架         │     │ Skill 工作流              │
   └──────────────────────┘     │ memory 存储后端           │
                                 │ UI 主题色                │
                                 └──────────────────────────┘
   框架开发者维护，一次写好      用户随意插拔，不用改框架

2. 开箱即用
   内置 web_search、文件读写、群聊界面、记忆系统
   配 2 个 Agent 就能跑起来，不是空壳

3. 模块之间只通过「数据」通信，不通过「代码」
4. 每个模块有降级行为——崩了不影响其他
5. 加功能 = 加插槽模块
```

## 三、插槽体系：Tool 和 Skill

### 3.1 Tool vs Skill 的本质区别

```
Tool  = 一次原子动作。做一件事，返回结果，结束。
Skill = 一个完整能力。可能需要多步、多个 Tool 接力、有条件判断。

类比:
  Tool  = 切菜、开火、倒油            ← 一个动作
  Skill = 做一道番茄炒蛋              ← 多个 Tool 组合 + 顺序 + 判断

例子:
  Tool  = web_search, fetch_url, read_file  ← 原子操作
  Skill = "日报生成"                        ← 搜索 → 整理 → 写文件
```

| 维度 | Tool | Skill |
|:---|:---|:---|
| 范围 | 单一原子操作 | 多步工作流 |
| 状态 | 无状态 | 有状态（跨步骤传递数据） |
| 耗时 | 秒级 | 分钟~小时级 |
| Agent 参与 | 一个 Agent 调一次 | 可能多个 Agent 接力 |
| 配置方式 | YAML 单文件 | YAML 多步骤编排 |

### 3.2 两种获取方式

```
用户获得 Tool/Skill 的方式:

方式 A：从社区下载                 方式 B：自己配 YAML
─────────────────                 ─────────────────
npm install @link/skill-xxx       新建 tools/my-tool.yaml
   ↓                                 ↓
装包，重启，即用                  写 YAML，重启，即用
   ↓                                 ↓
适合"拿来就用"的人                 适合有个性化需求的人

两种方式走的是同一个运行时底层，没有"二等公民"。
```

### 3.3 YAML 配置示例（入门级，零代码）

```yaml
# tools/rss-fetcher.yaml
name: fetch_rss
description: 抓取 RSS 订阅源的最新文章
execution:
  type: http
  url: "https://api.rss2json.com/v1/api.json?rss_url={{feedUrl}}"
parameters:
  feedUrl:
    type: string
    description: RSS 订阅地址
    required: true
```

```yaml
# tools/server-monitor.yaml
name: check_server
description: 检查服务器是否在线
execution:
  type: ssh
  host: "{{serverIp}}"
  command: "uptime && df -h"
  timeout: 30
parameters:
  serverIp:
    type: string
    required: true
```

### 3.4 内置执行器类型（框架提供）

| 类型 | 作用 | 适合场景 |
|:---|:----|:--------|
| `http` | 调 HTTP API | 搜索、抓网页、调第三方服务 |
| `command` | 本机执行命令 | 本地脚本、文件操作 |
| `ssh` | SSH 到远程执行 | 服务器管理、远程操作 |
| `docker` | Docker 容器执行（v2） | 隔离环境、代码执行 |
| `script` | 运行 JS 脚本（v2） | 复杂逻辑的 YAML 表达不了时 |

用户只需要配 `execution.type` + 参数，框架提供执行引擎。

## 四、社区 Skill 包的格式要求

这部分是社区开发者发布 Skill 时必须遵守的规范。

### 4.1 包命名规范

```
包名格式:        @link/skill-{name}

✅ 合法名称:     @link/skill-rss-reader
                @link/skill-server-monitor
                @link/skill-daily-journal

❌ 不合法:       @link/my-skill          ← 没有 skill- 前缀
                skill-rss-reader         ← 没有 @link/ 作用域
```

### 4.2 包入口文件格式

每个 Skill 包**必须**导出一个默认类，继承 `LinkSkill` 基类：

```javascript
// index.js — 每个 Skill 包的入口文件

const { LinkSkill } = require('@link/sdk');

class RssReaderSkill extends LinkSkill {
  // ─── 必填元数据 ───

  static id = 'rss-reader';                // 唯一 ID，全局不重复
  static version = '1.0.0';                // 语义化版本
  static linkVersion = '>=1.0.0';          // 兼容的 LINK 版本范围
  static displayName = 'RSS 阅读器';        // 人类可读的名称
  static description = '订阅和阅读 RSS 源';
  static author = 'link-contributor';
  static license = 'MIT';

  // ─── 必须实现的方法 ───

  /** 返回此包提供的所有 Tool */
  getTools() {
    return [
      {
        name: 'fetch_rss',
        displayName: '获取 RSS',
        description: '抓取指定 RSS 源的最新文章',
        parameters: {
          feedUrl: { type: 'string', description: 'RSS 地址', required: true },
          limit: { type: 'number', description: '返回条数', default: 10 },
        },
        execute: async (args, signal) => {
          const res = await fetch(`https://api.rss2json.com/v1/api.json?rss_url=${args.feedUrl}`);
          return res.text();
        },
      },
    ];
  }

  /** 返回此包提供的所有 Skill（工作流） */
  getSkills() {
    return [
      {
        name: 'daily_digest',
        displayName: '每日摘要',
        description: '抓取 RSS → 摘要 → 存笔记',
        steps: [
          { tool: 'fetch_rss', agent: 'my-agent' },
          { tool: 'summarize', agent: 'my-agent' },
          { tool: 'write_file', agent: 'my-agent' },
        ],
      },
    ];
  }

  // ─── 可选的生命周期钩子 ───

  /** 安装时调用（校验依赖、创建目录等） */
  async onInstall(ctx) { /* 可抛出错误阻止安装 */ }

  /** 卸载时调用（清理资源） */
  async onUninstall(ctx) {}

  /** 每次 LINK 启动时调用（检查环境、报告状态） */
  async onStartup(ctx) {
    return { status: 'ready' };
  }
}

module.exports = RssReaderSkill;
```

### 4.3 包目录结构

```
@link/skill-rss-reader/
├── package.json               ← 必须有，main 指向 index.js
├── index.js                   ← 入口，导出继承 LinkSkill 的类
├── README.md                  ← 说明文档
├── tools/                     ← 可选：Tool 的详细文档
│   └── fetch_rss.md
├── skills/                    ← 可选：Skill 的使用示例
│   └── daily_digest.md
├── link-config.example.js     ← 可选：安装后的配置建议
└── LICENSE                    ← 推荐 MIT
```

### 4.4 package.json 要求

```json
{
  "name": "@link/skill-rss-reader",
  "version": "1.0.0",
  "description": "订阅和阅读 RSS 源",
  "main": "index.js",
  "link": {
    "skill": true,
    "minLinkVersion": ">=1.0.0",
    "category": "content"
  },
  "keywords": ["link", "link-skill", "rss", "content"],
  "license": "MIT"
}
```

**说明**：
- `link.skill: true` — 告诉 LINK 这是一个 Skill 包（LINK 启动时扫描这个字段）
- `link.minLinkVersion` — 兼容的最低 LINK 版本
- `link.category` — 分类标签，社区市场用来归类

### 4.5 与 YAML 配置的关系

```
用户写 tools/my-tool.yaml
        ↓
LINK 的 YAML 适配器将其自动包装成 LinkSkill 对象
        ↓
与 npm install 安装的包进入同一套注册系统（ToolRegistry + SkillRegistry）
        ↓
Agent 调用时不知道工具来自 YAML 还是包，都一样用
```

**YAML 格式与包格式的对应关系：**

| 包格式 | YAML 格式 |
|:------|:---------|
| `name: 'fetch_rss'` | `name: fetch_rss` |
| `description: '...'` | `description: ...` |
| `parameters: { target: { type: 'string' } }` | `parameters: target: { type: string }` |
| `execute: async (args) => httpGet(url)` | `execution: { type: http, url: '...' }` |

**只有一个区别**：YAML 不支持写代码，所以 `execute` 函数通过 `execution.type`（http/command/ssh）来描述"怎么执行"，由 LINK 框架提供执行引擎。

### 4.6 发布与安装流程

```
社区开发者发布:
  1. 写 index.js，继承 LinkSkill
  2. npm publish --access public
  3. 在 LINK 社区市场注册（可选）

用户安装:
  npm install @link/skill-rss-reader

LINK 启动时自动加载:
  扫描 node_modules/@link/skill-*
     ↓
  检查 link.skill === true
     ↓
  检查 link.minLinkVersion 兼容
     ↓
  调用 onInstall() → onStartup()
     ↓
  注册 getTools() → ToolRegistry
  注册 getSkills() → SkillRegistry
     ↓
  Agent 对话中可直接使用
```

### 4.7 生态成熟度的三个阶段

```
阶段 1（现在）:
  ├── @link/sdk 尚未发布，格式在设计中
  ├── tools/ 直接用 YAML 配置
  └── 先跑通 YAML → 执行的链路

阶段 2（LINK v1.0 发布时）:
  ├── @link/sdk 发布，包含 LinkSkill 基类
  ├── 第一个参考 Skill 包（@link/skill-example）
  ├── 文档：如何写一个 Skill 包
  └── 第一个社区贡献的包

阶段 3（社区形成后）:
  ├── 社区市场（网页浏览 + 搜索 + 一键安装）
  ├── npm create link-skill 脚手架（生成包骨架）
  └── Skill 包质量指南 + 审核机制
```

## 五、内置模块

### 5.1 模块总览

| 模块 | 职责 | 用户需要做的 |
|:----|:----|:-----------|
| `@link/llm` | LLM 调用 + streaming + 健康检查 + 断路器 | 配置 API Key 和模型名 |
| `@link/agent-runtime` | tool_call → tool_result 循环引擎 | 内部依赖，用户不直接调 |
| `@link/memory` | 写入队列 + 四层压缩 + 上下文恢复 | 框架自动运行 |
| `@link/gateway` | HTTP 路由 + SSE 推送 + 默认前端 UI | 可换主题色 |
| `@link/agents` | @路由 + content classifier | 配 Agent 身份 |
| `@link/scheduler` | 定时推送 + 状态持久化 + 补发 | 配推送内容和时间 |
| `@link/knowledge` | 知识库索引 + 关键词检索 + 盲区检测 | 笔记按目录放好 |
| `@link/admin-ui` | **Web 管理面板（配置界面）** | ✅ 不写代码，浏览器里配置 |

### 5.2 模块 call: LLM 适配器

```javascript
// 4 个接口
await llm.call(agentId, messages)           // 同步调用
for await (const token of llm.stream(...))  // 流式调用
await llm.healthCheck()                     // 健康检查
llm.setProvider(config)                     // 运行时切换模型
```

支持多 provider 运行时切换，断路器自动降级。

### 5.3 模块 G: Agent Runtime

复用 `@openclaw/agent-core` 的 agentLoop 引擎（tool_call 循环）。prompt 构建由框架根据用户配置的 Agent 身份自动生成。

### 5.4 模块 B: Memory（四层压缩）

```
                   原始消息流 (rooms.json)
                       │
         每日 23:55 静默触发
                       │
                       ▼
┌────────────────────────────────────────────────────┐
│  Layer 1: 日摘要 (Daily Summary)                    │
│  位置: data/daily-summary/{roomId}/{YYYY-MM-DD}    │
│  保留: 最近 14 天                                    │
│  对用户: 完全不可见                                   │
└───────────────────────┬────────────────────────────┘
                        │
          周日 23:57 自动聚合
                        │
                        ▼
┌────────────────────────────────────────────────────┐
│  Layer 2: 周摘要 (Weekly Digest)                    │
│  位置: data/weekly-digest/week-{week}.md           │
└───────────────────────┬────────────────────────────┘
                        │
          周日 23:58 自动归档
                        │
                        ▼
┌────────────────────────────────────────────────────┐
│  Layer 3: 归档 (Archive)                           │
│  长期记录 + 状态更新                                 │
└───────────────────────┬────────────────────────────┘
                        │
            检测到重大事件
                        │
                        ▼
┌────────────────────────────────────────────────────┐
│  Layer 4: 里程碑 (Milestones)                      │
│  自动记录关键节点                                    │
└────────────────────────────────────────────────────┘
```

上下文恢复增强：

```
buildTranscript() = 最近 N 条消息
                  + 最近 7 天的日摘要
                  + 用户的核心身份
                  + 当前进度/计划
```

所有的路径、文件名、保留策略都可通过 `link.config.js` 配置。

### 5.5 模块 A: Gateway

只做三件事：HTTP 路由、SSE 推送、前端 UI。业务逻辑委托给其他模块。

前端支持 streaming（打字机效果），默认提供深色主题，可通过 `public/theme.css` 自定义。

### 5.6 模块 C: Agents

框架层：
- @路由解析 + content classifier（轻量 LLM 调用，自动判断消息该谁回应）
- Agent 身份从用户配置读取，框架负责注入

用户在 `link.config.js` 里配：

```javascript
agents: [
  { id: 'coach', name: '我的教练',
    prompt: '你是我的成长教练，帮我拆解目标', autoReply: true },
  { id: 'friend', name: '我的朋友',
    prompt: '你是一个温暖的朋友', autoReply: false },
]
```

### 5.7 模块 D: Scheduler

定时任务在 `link.config.js` 里配：

```javascript
pushSchedule: [
  { hour: 9, minute: 0, agent: 'coach',
    prompt: '今天的目标是什么？', desc: '晨间提醒' },
]
```

支持静默任务（用户不可见）、状态持久化、重启补发。

### 5.8 模块 E: Knowledge

- 索引构建：遍历用户笔记目录 → `knowledge_index.json`
- 检索：关键词匹配（tags → description → title）
- 盲区检测：对比已学知识和新遇到的问题

### 5.9 模块 H: Admin UI（管理面板）

**目标**：让非技术用户在不碰代码、不写 YAML 的情况下，通过浏览器完成所有配置。


**核心设计原则**：

```
管理面板的每一次操作 = 修改 link.config.js 或写 tools/*.yaml
不引入额外的数据库，没有"UI 配了一套，文件里是另一套"的问题。

例如用户在 UI 里新增了一个 Agent:
  ① 管理面板修改 link.config.js
  ② LINK 检测到配置变化，热重载
  ③ 新的 Agent 立刻在聊天界面可用

如果用户想切回手动配置，直接编辑 link.config.js → 保存 → 面板自动同步。
两种方式可以混用，不会冲突。
```

**实现方式**：

```
@link/admin-ui 是一个独立的前端应用（React/Vue）
嵌入在 @link/gateway 的 /admin 路由下

后端只需要暴露几个 API:
  GET  /api/config          ← 读取当前配置
  PUT  /api/config          ← 更新配置
  GET  /api/skills/available ← 社区可安装的 Skill 列表
  POST /api/skills/install  ← 安装一个 Skill 包

```
